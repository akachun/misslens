# MissLens 데모 시나리오

과정 평가에서 보여 줄 패턴의 우선순위는 **멀티 에이전트 > RAG > HITL**이다. 10분 안팎으로, 한 번의 흐름 안에서 세 가지가 모두 드러나게 짠다. 화면은 Streamlit(`streamlit run app/main.py`), 문제가 생기면 같은 단계를 CLI로 대체한다.

## 준비 (시연 30분 전)

| 확인 | 명령 | 기대 결과 |
|---|---|---|
| 모델 응답 | `python scripts/probe_models.py` | 역할마다 응답하는 엔드포인트가 1개 이상(할당량 초과면 다음 엔드포인트로 자동 전환) |
| 실호출 스모크 | `pytest -m live` | 8개 통과(문제 생성, 라우터, Planner) |
| 색인 | `python -m misslens.cli search "tool_choice" --task 2.3` | 시험 가이드와 수집한 교안 청크가 나옴 |
| 그래프 그림 | README의 Mermaid 그림 | Supervisor → 6개 에이전트, interrupt① ② 표시 |
| 미리 푼 세트 | `MISSLENS_SANDBOX=1 python -m misslens.cli plan -n 3` 한 번 | 현황 탭에 숫자가 있고, 진단 일치율이 보임 |
| 앱 | `MISSLENS_SANDBOX=1 streamlit run app/main.py` | 탭 4개와 '샌드박스 모드' 안내가 열림. 처음 열 때 bge-m3 로드로 10초 안팎 걸림. 시연 중 일부러 틀린 답이 실제 학습 기록에 섞이지 않음 |

문제 하나를 만드는 데 30초~1분이 걸린다(Sonnet 생성 + Haiku 근거 검증, 실패하면 재생성). 그래서 시연 세트는 3문제로 하고, 첫 문제가 준비되면 바로 풀기 시작한다.

## 흐름

### 1. 구조 소개 (1분) — 멀티 에이전트

- README의 '한눈에 보는 구조'와 '에이전트별 그래프'를 띄운다. Supervisor 하나가 Planner·Generator·Grader·Coach·Reporter·Collector·Ingest로 요청을 보내고, interrupt는 계획 승인(①)과 로그인 대기(②) 두 곳뿐이다. '적용한 구조와 패턴' 표로 멀티 에이전트·RAG·HITL·ReAct tool 사용이 어디에 있는지 짚는다.
- 말할 것: "버튼과 명령은 모델 없이 바로 분기하고, 자유 문장만 Haiku가 의도를 분류합니다. 애매하면 실행하지 않습니다."

### 2. 자연어 지시 (1분) — 멀티 에이전트(Supervisor 라우팅)

- 사이드바에 `오늘 뭐 공부하면 좋을지 계획 세워줘`를 쓰고 **Ctrl+Enter(맥 ⌘+Enter)** 또는 '보내기'(Enter는 줄바꿈) → "계획을 만들었습니다. '계획' 탭에서 승인하세요."
- 이어서 `점심 뭐 먹지?` → "무엇을 할지 확실하지 않아 실행하지 않았습니다…" (저신뢰는 실행하지 않음)
- 대체 경로: `python -m misslens.cli ask "오늘 뭐 공부하면 좋을지 계획 세워줘"`

### 3. 계획 승인 (2분) — HITL interrupt①

- 계획 탭: 영역별 비중·출제 항목·정답률과 오늘 문제 수, Planner의 한국어 근거.
- 문제 수를 3개로 고친다(예: d2 2개, d3 1개). 일부러 합계를 0으로 만들면 이유와 함께 다시 묻는 것도 보여 줄 수 있다.
- **브라우저를 새로고침한다** → 주소의 `plan` 값으로 같은 승인 화면이 그대로 돌아온다(체크포인터에서 interrupt를 다시 읽음).
- 승인 → "계획대로 세트를 만들고 있습니다. '학습' 탭에서 푸세요."
- 대체 경로: `python -m misslens.cli plan -n 3` (Enter=승인, e=고치기, q=취소)

### 4. 세트 풀이 (2분) — RAG

- 학습 탭: 첫 문제가 준비되면 바로 시작, 나머지는 뒤에서 생성된다. 영어 지문, 실제 시험처럼 해설 없이 푼다.
- 말할 것: "문제마다 세부 항목에 태그된 자료를 하이브리드 검색(bge-m3 + BM25)으로 가져와 근거로 쓰고, Haiku가 그 자료로 정답·오답 근거·지어낸 플래그를 검증합니다. 통과하지 못한 문제는 보여 주지도 기록하지도 않습니다."
- 보여 줄 근거: 다른 창에서 `python -m misslens.cli search "<문제의 핵심어>" --task <문제의 세부 항목>` → 수집한 교안 청크가 상위에 나옴.
- 하나는 일부러 틀린다(조건 문구를 놓친 척, 다른 보기 선택).

### 5. 리뷰와 진단 (2분) — 핵심 기능

- 세트 제출 → 리뷰: 오답과 맞힌 문제 일부(미끼)를 한국어로 다시 푼다. 틀렸던 문제를 한국어로는 맞히고 '확신'을 체크한다.
- 자기 판단: 정답만 보고 "알았는데 조건을 놓침(해석)"을 고른다(해설 전).
- 진단: **해석 실수** 판정, 지문 안에 놓친 조건 문구가 강조된다. 각 문제에 '한국어 재질문: A 선택(정답) · 확신 → 해석 실수'처럼 판정 근거가 나오고, '판정은 어떻게 정해지나요?'를 펼쳐 표를 보여 준다. 미끼 기준선이 함께 나온다.
- 말할 것: "한국어로는 맞혔으니 개념은 알았고 영어 지문의 조건을 놓친 것입니다. 맞힌 문제도 섞어 다시 물어서, '다시 보면 맞힌다' 효과를 기준선으로 따로 봅니다."
- '코치 해설(자료 검색)'을 누른다 → 기본 해설은 그대로 두고 아래에 코치 해설이 붙는다. 코치 에이전트가 `search_material`(수집한 교안 검색)과 `learner_history`(내 기록)를 직접 불러 해설을 쓰고, 근거 출처(레슨 링크·`guide.pdf p.N`)와 사용한 도구 순서가 표시된다(tool 사용 에이전트, D44).
- '코치에게 질문'에 "이 개념을 실제 코드에서는 어떻게 설정하나요?"나 "Skilljar 강의에서 관련 내용을 찾아줘"처럼 이어서 묻는다(해설 없이 바로 물어도 되고, 맞힌 문제도 펼쳐서 물을 수 있다) → 코치가 앞의 대화를 기억한 채 다시 자료를 찾아 답한다. 출처 링크를 눌러 수집한 레슨 원문으로 들어가 보여 준다(D47).

- 진단 아래 '이번 세트 단어장'(10초 안팎): 정답을 가른 조건 표현·기술 용어와 뜻, 원문 문장 강조. '외웠어요' 표시 → '단어장' 탭에서 누적 목록(D54).

### 6. 현황 (1분)

- 현황 탭: 범위(30개 세부 항목 중 출제된 수), 해석 실수 비율과 미끼 기준선(나란히), 영역별 정답률, 놓친 문구 순위, 진단 일치율(내 판단과).
- 말할 것: "다음 계획은 이 숫자로 다시 세웁니다(범위 먼저, 그다음 약점)."

### 7. 로그인 세션 수집 (1분) — HITL interrupt②

라이브로 세션 만료를 만들기 어려우므로 녹화나 테스트로 보여 준다.

- 자료 탭: 색인 현황(세부 항목 30개 중 자료가 있는 수, 수집한 코스 레슨 수).
- 설명: 사람이 직접 로그인한 브라우저 프로필로, `sources.yaml`에 적힌 코스의 레슨만 읽는다. 세션이 만료되면 수집이 멈추고 "로그인이 필요합니다"와 '완료/중단' 버튼이 뜨며, 완료를 누르면 멈춘 레슨부터 이어간다.
- 근거: `pytest tests/test_collector.py -k expired -v`(만료 → interrupt → 같은 URL 재개), `pytest tests/test_supervisor.py -k collect -v`(Supervisor를 거쳐도 interrupt가 올라옴).

## 실패할 때

| 상황 | 대응 |
|---|---|
| Bedrock 호출 제한·할당량 초과 | 라우터가 엔드포인트를 자동 전환(`us.` 2곳 → `global.` 3곳). 계속 막히면 `BEDROCK_ENDPOINTS=usw2-us,use1-global`로 순서 변경 |
| 문제 생성이 느리거나 연속 실패 | 준비 단계에서 미리 만든 세트(`plan -n 3`)로 리뷰·진단·현황을 보여 줌. 실패 이유는 현황 탭 '생성 실패'에 남음 |
| Streamlit 오류 | 같은 단계를 CLI(`ask`, `plan`, `status`)로 진행 |
| 시연 중 창이 닫히거나 서버가 재시작됨 | 학습 탭 '이어 풀기'에서 세트를 다시 연다(푼 답은 저장돼 있음, 생성이 멈췄으면 '남은 문제 생성'). 제출한 세트는 '지난 세트', 계획은 계획 탭 '최근 계획'에서 다시 연다 |
| 시연 중 `.env` 키 교체 | 서버는 시작할 때 키를 읽으므로 재시작해야 반영된다. 제출 전 답안은 세션에만 있으니 세트를 제출한 뒤 재시작하고, 주소의 `?set=` 값으로 같은 세트로 돌아온다. 제출·리뷰·판정은 모델 없이 동작한다 |
| 수집 시연 불가 | 테스트 실행 결과와 `data/sources/collected/`의 수집본, 색인 현황으로 대체 |
