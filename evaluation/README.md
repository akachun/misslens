# 평가 라운드 기록

문제 생성 품질을 라운드마다 같은 입력으로 다시 재고, 바꾼 것과 결과를 남긴다(D58, D59). 검색 품질 점수는 `evals/ccar-f/retrieval_baseline.json`과 `docs/testing.md` §3에 따로 있다.

## 방법

| 구성 | 내용 |
|---|---|
| 인-아웃 세트 | `evals/ccar-f/question_set.yaml`. 입력은 세부 항목 20개, 기대 판정은 1라운드 문제에 대한 외부 검토 결과(Claude Opus·GPT 교차 검토 합의) |
| 생성 | 라운드마다 같은 세부 항목 20개로 새로 만든다. 학습 기록과 섞이지 않게 `data/eval/question_rounds.sqlite`(git 제외)에 저장 |
| LLM-as-Judge | `judge` 역할(Sonnet 4.6). 문제마다 정답을 숨기고 직접 풀기 1회, 오답 보기별 세부 판정 1회. 요약 판정(OK·수정·폐기)은 세부 판정에서 코드가 계산 |
| 외부 검토 | `export-questions` 또는 라운드 실행이 만든 `data/eval/round<N>_questions.md`를 Opus·GPT에 넣어 교차 검토(`docs/testing.md` §5) |
| 실행 | `python -m misslens.cli question-eval --round N --notes "바꾼 것"` (1라운드: `--existing`, 다시 채점: `--from-set ID`) |

지표: 판정기 OK 비율, 오답 근거(`violates`) 유효, 정답이 하나뿐, 표시된 정답이 맞음, 직접 푼 답 = 정답, 사실 확인됨, 번역 정확, 시험 적합성, 생성 성공·첫 시도 통과·평균 시도.

RAGAS 지표와의 대응: 검색 쪽 context recall·precision은 정답 질의 30개의 hit@k·MRR(`retrieval-eval`)이, 생성 쪽 faithfulness는 '표시된 정답이 맞음·사실 확인됨'(근거 발췌 기준)이 맡는다.

|---|---|---|---|---|---|---|---|
| 1 | 기준선(기존 지시문, 샌드박스 20문제). 외부 검토 OK 1/20 | 25% | 50% | 90% | 50% | 65% | [round1_report.md](round1_report.md) |

두 라운드 모두 판정기 v2로 채점했다. v1 결과는 `round*_judge_v1_report.md`에 있다.

## 판정기 보정

판정기는 생성기와 같은 계열이라 관대할 수 있어서, 1라운드 문제에 대한 외부 검토(다른 회사 모델 포함)와 비교해 고쳤다.

| 판정기 | 방식 | OK 비율(외부 5%) | OK/비OK 일치 | violates 오류 찾음 | 시험 적합성 찾음 |
|---|---|---|---|---|---|
| v1 | 항목별 참/거짓 한 번 | 80% | 25% | 3/14 | 0/5 |
| v2 | 오답 보기마다 violates 종류(요구사항·제안·관찰·배경·없음), 진짜 틀린 이유, 정답 가능성을 따로 답하고 요약은 코드가 계산 | 25% | 80% | 9/14 | 3/5 |

남은 한계:
- 복수 정답(1/4)과 번역(0/3)은 아직 잘 못 찾는다.
- 근거 자료에 *없는* 내용을 '사실 오류'로 넣는 경향이 있다(1라운드 6건, 외부 검토 2건).
- 외부 기대 판정에 OK가 1개뿐이라, 판정기가 너무 엄격해지는 쪽은 측정이 약하다.
- 2라운드 문제는 판정 기준과 같은 내용을 담은 지시문으로 만들었으므로, 판정기 점수만으로는 부족하다. `data/eval/round2_questions.md`를 외부 검토로 확인하는 것이 기준이다.

## 발견과 다음 라운드

- **2라운드 결과:** 복수 정답(90→100%), 사실(50→83%), 시험 적합성(65→83%)은 좋아졌다. 그러나 violates 유효는 50%로 그대로다.
- **오답 보기별 분석:** 관찰·진단 7→3, 지문에 없음 2→0, 요구사항이지만 진짜 이유가 아님 7→2로 줄었다. 배경 사실은 4→5로 남았다.
- **원인:** 남은 오류의 대부분은 *개념 때문에 틀린 오답*(안티패턴, 기술 사실 오해)이다. 현재 설계는 모든 오답에 지문 속 조건을 붙이게 강제하므로(D40, CLAUDE.md 규칙 3), 붙일 요구사항이 없으면 모델이 배경 문장을 고른다. 지시문으로는 더 줄이기 어렵다.
- **3라운드 후보(학습자 결정 필요, 규칙 3 변경):** 개념 오답은 `violates`를 비우게 허용하고(`violates: null` + `concept_reason`), 진단에서 그런 보기를 고른 경우 '놓친 문구' 없이 개념 실수로 기록한다.
