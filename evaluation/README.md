| 라운드 | 바꾼 것 | **통과** | positive | negative | edge | guardrail | context_precision | faithfulness | answer_relevancy | 리포트 |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 | 기준선(첫 구현) | **14/20** | 6/8 | 2/4 | 3/5 | 3/3 | 0.81 | 0.80 | 0.77 | [query_round1_report.md](query_round1_report.md) |
| 2 | 라우터: 설명 요청·세부 항목 기록 질문은 코치 질문, 모호한 말은 낮은 신뢰도. 질의응답: 공식 문서 권유·연습 세트 안내·되묻기 하나 | **20/20** | 8/8 | 4/4 | 5/5 | 3/3 | 0.87 | 0.79 | 0.73 | [query_round2_report.md](query_round2_report.md) |

- RAGAS 표본은 근거를 찾아 답한 질의만이다(1라운드 8건, 2라운드 9건). '자료에 없음' 답(9번)은 answer_relevancy가 0으로 나온다.

## 문제 생성 품질 라운드 (D59)

## 방법

| 구성 | 내용 |
|---|---|
| 인-아웃 세트 | `evals/ccar-f/question_set.yaml`. 입력은 세부 항목 20개, 기대 판정은 1라운드 문제에 대한 외부 검토 결과(Claude Opus·GPT 교차 검토 합의) |
| 생성 | 라운드마다 같은 세부 항목 20개로 새로 만든다. 학습 기록과 섞이지 않게 `data/eval/question_rounds.sqlite`(git 제외)에 저장 |
| LLM-as-Judge | `judge` 역할(Sonnet 4.6). 문제마다 정답을 숨기고 직접 풀기 1회, 오답 보기별 세부 판정 1회. 요약 판정(OK·수정·폐기)은 세부 판정에서 코드가 계산 |
| 외부 검토 | `export-questions` 또는 라운드 실행이 만든 `data/eval/round<N>_questions.md`를 Opus·GPT에 넣어 교차 검토(`docs/testing.md` §5) |
| 실행 | `python -m misslens.cli question-eval --round N --notes "바꾼 것"` (1라운드: `--existing`, 다시 채점: `--from-set ID`) |

지표: 판정기 OK 비율, 오답 근거(`violates`) 유효, 정답이 하나뿐, 표시된 정답이 맞음, 직접 푼 답 = 정답, 사실 확인됨, 번역 정확, 시험 적합성, 생성 성공·첫 시도 통과·평균 시도.

RAGAS 지표와의 대응: 검색 쪽 context recall·precision은 정답 질의 30개의 hit@k·MRR(`retrieval-eval`)이, 생성 쪽 faithfulness는 '표시된 정답이 맞음·사실 확인됨'(근거 발췌 기준)이 맡는다.

## 라운드 요약

| 라운드 | 바꾼 것 | **외부 검토 OK** | 판정기 OK | violates 유효(판정기) | 정답 하나 | 사실 확인 | 시험 적합성 | 리포트 |
|---|---|---|---|---|---|---|---|---|
| 1 | 기준선(기존 지시문, 샌드박스 20문제) | **5%** (1/20) | 25% | 50% | 90% | 50% | 65% | [round1_report.md](round1_report.md) |
| 2 | 출제·근거 확인 지시문 보강(요구사항만 key constraint로, 근거가 인정하는 대안 금지, 정답이 지문 복사 금지, 중복 오개념 금지) | **22%** (4/18) | 44% | 50% | 100% | 83% | 83% | [round2_report.md](round2_report.md) |

- 외부 검토는 Claude Opus와 GPT가 따로 검토한 뒤 서로의 결과를 교차 확인한 최종안의 합의다. 2라운드는 두 검토의 판정이 18문제 모두 같았다(원본은 `data/eval/round2/`, git 제외).
- 판정기 열은 두 라운드 모두 판정기 v2로 채점한 값이다. v1 결과는 `round*_judge_v1_report.md`에 있다.
- 2라운드는 20개 중 18개 생성(4.1, 3.3 실패). 첫 시도 통과 83%, 평균 시도 1.4회.

## 판정기 보정

판정기는 생성기와 같은 계열이라 관대할 수 있다. 그래서 라운드마다 외부 검토 합의와 비교한다. 외부 라벨은 `evals/ccar-f/question_set.yaml`에 라운드별로(`external`=1라운드, `round2`=2라운드) 넣고, `question-eval --round N --relabel`로 모델 호출 없이 다시 계산한다.

| 판정기 | 방식 | 1라운드 OK/비OK 일치 | 2라운드 OK/비OK 일치 | violates 오류 찾음 |
|---|---|---|---|---|
| v1 | 항목별 참/거짓 한 번 | 25% (OK 80% vs 외부 5%) | - | 3/14 |
| v2 | 오답 보기마다 violates 종류(요구사항·제안·관찰·배경·없음), 진짜 틀린 이유, 정답 가능성을 따로 답하고 요약은 코드가 계산 | 80% | 67% | 1R 9/14, 2R 8/14 |

2라운드 외부 라벨은 오답 보기 단위까지 있어서 판정기의 강약을 더 자세히 볼 수 있다.

| 2라운드, 판정기 v2 vs 외부 합의 | 값 |
|---|---|
| violates 종류 분류(요구사항·제안·관찰·배경) 일치 | **92%** (51개 보기) |
| 보기 유효 여부(요구사항이고 틀린 진짜 이유인가) 일치 | 74% (49개) |
| 외부가 무효로 본 보기를 판정기도 찾음 | **44%** (8/18) |
| 외부가 유효로 본 보기를 판정기가 무효로 봄(너무 엄격) | 10% (3/31) |
| 외부 OK 문제를 판정기도 OK로 봄 | 75% (3/4) |
| 외부가 수정으로 본 문제를 판정기가 OK로 넘김(너무 관대) | 5개 (Q7, Q9, Q10, Q14, Q17) |

해석과 남은 한계:
- 판정기는 violates 문구가 *무엇인지*는 잘 가르지만, 요구사항 문구가 그 보기가 *틀린 진짜 이유인지*는 전혀 보지 못한다. 외부가 무효로 본 보기 19개를 나누면 '요구사항이 아닌 문구'(배경·관찰·제안) 9개 중 8개는 판정기도 찾았지만, '요구사항이지만 진짜 이유가 아님' 8개는 하나도 찾지 못했다(나머지 2개는 외부 의견이 종류에서 갈림). 판정기 v3의 개선 지점이다.
- 너무 엄격한 쪽의 오류는 작다(유효 보기 오판 10%, 외부 OK 4개 중 3개 인정).
- 복수 정답(1라운드 1/4, 2라운드 0/2)과 지문 모순(2라운드 1/6)은 아직 잘 못 찾는다.
- 근거 자료에 *없는* 내용을 '사실 오류'로 넣는 경향이 있다(1라운드 6건, 외부 검토 2건).
- 2라운드 문제는 판정 기준과 같은 내용을 담은 지시문으로 만들었다. 그래서 판정기 점수(OK 44%)가 외부(22%)보다 높게 나온다. 품질 판단의 기준은 외부 검토이고, 판정기는 라운드 사이의 빠른 비교용이다.

## 발견과 다음 라운드

- **지시문 보강은 효과가 있었다:** 외부 검토 OK가 5%에서 22%로 올랐다. 정답 오류는 두 라운드 모두 0이다.
- **가장 큰 문제는 여전히 violates다:** 외부 검토가 18문제 중 14문제에서 violates를 지적했다. 무효 보기 19개는 '요구사항이 아닌 문구'(배경·관찰·제안) 9개, '요구사항이지만 틀린 진짜 이유가 아님' 8개, 종류가 갈린 2개다.
- **원인:** 둘 다 같은 뿌리다. 개념 때문에 틀린 오답(안티패턴, 기술 사실 오해)에도 지문 속 조건을 하나 붙이게 강제하므로(D40, CLAUDE.md 규칙 3), 모델이 배경 문장이나 관련 없는 요구사항을 고른다. 지시문으로는 더 줄이기 어렵다.
- **3라운드 후보(학습자 결정 필요, 규칙 3 변경):** 개념 오답은 `violates`를 비우게 허용하고(`violates: null` + `concept_reason`), 진단에서 그런 보기를 고른 경우 '놓친 문구' 없이 개념 실수로 기록한다. 지문 모순(stem)이 2라운드에서 6문제로 늘어난 것도 함께 본다(지시문이 요구사항을 지문에 더 많이 넣게 하면서 문장끼리 충돌).
- **판정기 v3 후보:** 오답 보기마다 "이 요구사항을 지켜도 이 보기가 여전히 틀리는가"를 따로 묻는다(진짜 이유 판정 보강).
